  This network's firewall decrypts and re-signs HTTPS traffic before it reaches you.

   ```
   ! NODE_EXTRA_CA_CERTS="C:\path\to\fortinet-ca.crt" npm install @monaco-editor/react monaco-editor
   ```

**Scenario data (`src/data/challenge-001/`)**
- `challenge.ts`, `logs.ts`, `files.ts` and `index.ts` hold the challenge and its files. `files.ts` contains 14 files across Markdown, JSON, TypeScript, JavaScript and log.

- The logs follow two login attempts in a row: login succeeds (200), the dashboard requests get 401, the client reports the error, and the user is sent back to the login page. Every log line matches a `logger` call in the code.
- `answer-key.server.ts` holds the provisional root cause. It starts with `import "server-only"`, so any client import fails the build, and nothing imports it yet.
- The removed `workspace-placeholder.ts` and `CodeEditorPlaceholder.tsx` show as deleted.

**Provisional root cause:**
- Login sets the session cookie as a signed cookie (`signed: true`).
- With `cookieParser(secret)`, signed cookies end up in `req.signedCookies`, not `req.cookies`.
- `authenticate` reads `req.cookies.sid`, which is always empty, so every protected request gets a 401.
- The logout route reads `req.signedCookies` correctly, which gives learners something to compare against.
- Nothing in learner-visible comments, logs or the incident text names the cause.

**Logic (`src/lib/`)**
- `file-tree.ts` builds the folder tree from the file list, folders first.
- `file-language.ts` picks the editor language from the file extension.
- `monaco-setup.ts` defines the `buglab-dark` theme from the existing colours and a custom `log` highlighter. It also turns off TypeScript's "cannot find module" errors, using Monaco 0.57's new `monaco.typescript` API.

**Client components (`src/components/workspace/`)**

- **`FileExplorer.tsx` and `FileTreeItem.tsx`:** an accessible tree. Tab reaches one item at a time. ↑/↓ move, → expands or moves into a folder, ← collapses or moves to the parent, Home/End jump to the ends, and Enter/Space opens a file or toggles a folder. ## Limitations and what to watch for when testing

- **Monaco loads from jsDelivr.** I pinned it to `monaco-editor@0.57.0` in `MonacoEditor.tsx`. If you upgrade the package, update that constant to match. On the FortiGate network the CDN may be blocked; you'd see the error message, not a broken page.
- **No cross-file code intelligence.** TypeScript semantic errors are turned off and there's no go-to-definition between files. You still get syntax highlighting and syntax errors.
- **Tab close buttons are skipped by Tab.** That avoids nesting buttons inside the tab list. Keyboard users close tabs with Delete, which the tabs announce via `aria-keyshortcuts`. Screen reader behaviour is worth a quick check.
- **Nothing persists.** A reload resets tabs and folders, and closed files keep their Monaco model in memory. Both are acceptable for this stage.
- **The answer key is provisional and unused.** It needs aligning with Haboon's engine before any validation work.
- **On mobile** the Explorer is capped at about 18rem tall and scrolls, and the editor has a fixed minimum height.

When you commit, include `.claude-logs/` and the `package.json`/`package-lock.json` changes from your install, per `CLAUDE.md`.

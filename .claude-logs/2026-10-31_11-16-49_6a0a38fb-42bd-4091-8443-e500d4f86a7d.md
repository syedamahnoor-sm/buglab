  This network's firewall decrypts and re-signs HTTPS traffic before it reaches you.

   ```
   ! NODE_EXTRA_CA_CERTS="C:\path\to\fortinet-ca.crt" npm install @monaco-editor/react monaco-editor
   ```

Draft options (IDs are descriptive slugs, so the ID alone doesn't give the answer away):

2. Sessions expire too early (TTL or unit mismatch)
3. **The middleware reads the session ID from unsigned cookies, but login issues a signed cookie** ← correct

## 3. Server side (all `import "server-only"`)

```
src/app/api/challenges/[challengeId]/diagnosis/route.ts   POST, uses ctx.params (awaited)
src/server/diagnosis/registry.ts                          challengeId → { answer key, valid evidence IDs }
src/server/diagnosis/evaluate.ts                          pure: (submission, key) → result
src/server/diagnosis/attempt-limiter.ts                   in-memory limiter, injectable clock
src/lib/diagnosis/validate.ts                             pure, shared with the client (no secrets)
```

**How a request is handled:**
1. **Request checks.** The method must be POST. `Content-Type` must be `application/json`, otherwise 415. That requirement also forces a CORS preflight for cross-site requests. If an `Origin` header is present it must match the host, otherwise 403. The body is read as text and capped at 16 KB, otherwise 413.
2. **Challenge ID.** It must be in the registry, otherwise 404 with a generic message.
3. **Parse and validate.** `JSON.parse` sits inside a try/catch, and everything is validated with the shared validator:
   - field types are checked;
   - `rootCauseId` must be one of the challenge's option IDs;
   - control characters are stripped from the explanation and its length checked;
   - evidence refs must have the right shape, exist in the scenario, and are de-duplicated.

   Failures return 400 with per-field messages that never mention correctness.
4. **Attempt limit.** Over the limit returns 429 with `Retry-After`.
5. **Evaluate.** Compare `rootCauseId` with the key on the server, then build the feedback.
   - **Wrong answer:** that option's hint, plus general evidence advice, for example "none of your evidence comes from the Network tab". It never says which evidence is key.
   - **Right answer:** the resolution summary, plus how many key observations your evidence covered.
6. **Respond** with `Cache-Control: no-store`. The explanation text is never echoed back or logged.

Only a correct answer reveals anything from the key, and only that answer's own resolution summary. The correct option ID never appears in any response.

## 4. Attempt limiting

- **Anonymous attempt cookie.** `buglab_attempt` is a random ID set on the first submission (`HttpOnly; SameSite=Strict; Path=/api`). It allows **3 wrong answers per 10 minutes per challenge**. When the window expires, the counter resets.
- **Per-IP throttle**, so clearing the cookie doesn't reset everything. It allows **10 submissions per 10 minutes per client address**, taken from the first `X-Forwarded-For` hop and otherwise a shared "unknown" bucket.
- **A correct answer is final.** Once a session gets it right, later submissions return the same result and don't count.

Honest limits:
- **Memory only.** Counts live in the server's memory, so they reset on restart and aren't shared between instances or serverless functions. A database or engine-side store would replace this later.
- **The IP can be faked** unless the app sits behind a proxy that sets it reliably.
- **Guessing is slowed, not prevented.** With 5 options, someone determined can still guess in about 2 windows. Making the evidence count toward correctness would make guessing harder. Question 2 covers that.

## 5. Client side

- **`lib/diagnosis/client.ts`**: `submitDiagnosis(challengeId, submission, signal)`. It has a 15-second timeout and turns network errors or bad responses into `{ status: "error" }`.
- **`useDiagnosisSubmission`**, a client state machine separate from both the investigation controller and the engine:
  - **States:** `idle → submitting → correct | incorrect | rate-limited | error`.
  - **Form state:** the chosen option and explanation draft, kept in memory.
  - **Retry:** after an error it resends the same payload. After a wrong answer the form stays filled in for revision.
  - **No double submits:** they're blocked, and an in-flight request is cancelled if the component unmounts.
- **`DiagnosisPanel`**, rewritten as a form with small parts:
  - **`RootCauseOptions`:** native radio buttons in a `fieldset` with a `legend`.
  - **`ExplanationField`:** a textarea with a character counter, `aria-invalid`, and `aria-describedby` linking it to its error.
  - **`EvidenceReview`:** the current live list with a required minimum of 1, plus a "Manage in Notes" button that switches the console to the Notes tab.
  - **`DiagnosisResult`:** an `aria-live` region with the success, wrong-answer, rate-limit and error views. The rate-limit view counts down until you can retry. Each view has a retry or "Revise" action.
  - **On submit:** client-side checks run first using the shared validator, and focus moves to the first invalid field. The server checks everything again regardless.
  - **After a correct answer:** the form becomes read-only.
- **Layout:**
  - On large screens the right column's console/diagnosis split changes from 3:2 to **1:1**, because the form needs more room. Its body already scrolls.
  - On mobile and tablet, panels just stack as they do now.
  - The Monaco editor, Explorer, Logs, Network and Notes don't change. The console gains a small way for the Diagnosis panel to switch it to the Notes tab.

## Security limitations

- **The limits are best-effort, not production-grade.** Counts live in the server's memory, so they reset on restart and aren't shared between instances or serverless functions.
- **Clearing the cookie gets around the limit when no proxy is trusted.** That's the default. Set `BUGLAB_TRUSTED_PROXY_HOPS=N` only when exactly N trusted proxies append to `X-Forwarded-For`. That enables the 10-per-10-minutes IP limit, and spoofed leftmost entries are ignored.
- **With 5 options, determined guessing is slowed, not prevented.**
- **The correct option's ID is public, as one of five choices.** Nothing marks it as correct. The answer only appears after a correct submission, and only as the resolution summary.
- **Basic CSRF protection only.** Cross-site requests are blocked by requiring a JSON content type (which forces a browser preflight) and checking the `Origin` header. There are no CSRF tokens.
